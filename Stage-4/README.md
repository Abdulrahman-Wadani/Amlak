## 5. Team Progress Review

The team will review project progress regularly to identify blockers, update task statuses, and ensure that deadlines remain achievable.

During each review, team members should report:

1. Work completed since the previous review.
2. Current development progress.
3. Remaining work and the estimated completion date.
4. Any blockers or dependencies.
5. Links to commits, pull requests, or completed deliverables.

**Review Frequency:** Weekly, with additional coordination when tasks depend on each other.

## 6. Task Dependencies

The following dependencies should be considered when coordinating development:

- The project requirements should be finalized before implementation decisions are considered complete.
- The class design and database structure should be available before dependent backend operations are finalized.
- Authentication endpoints and other backend routes should follow the agreed requirements and data models.
- React pages can be developed in parallel, using agreed API contracts or mock data until the backend endpoints are available.
- Integration and final testing should take place after the required frontend and backend functionality is available.

---

## 7. Definition of Done

A task is considered complete only when:

- The implementation meets its acceptance criteria.
- The code or documentation has been committed and pushed to the repository, where applicable.
- Required tests have passed.
- The implementation has been reviewed where applicable.
- Relevant documentation has been updated.
- The task status has been changed to `Done` on the project board.
